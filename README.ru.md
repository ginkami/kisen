# shogi·world

[![English version](https://img.shields.io/badge/English-README.md-blue)](./README.md)

Одностраничное приложение для создания, ведения и публикации турниров по сёги (японским шахматам). Разработано как MVP с чистой архитектурой, изолирующей слой Firebase, чтобы в будущем миграция на собственный бэкенд была максимально простой.

## Возможности

- **Свободная турнирная система** — любой набор игр группы участников можно представить в виде туров и кросс-таблицы. Поддерживаются швейцарская система, Мак-Магон, круговая система, матчи, олимпийка и смешанные форматы.
- **Ролевая модель доступа** — пользователи, менеджеры и администраторы с правилами безопасности Firestore.
- **Аутентификация** — регистрация по email/паролю и вход через Google через Firebase Auth.
- **Интернационализация** — интерфейс на английском и русском языках.
- **Адаптивный интерфейс** — Tailwind CSS v4 + daisyui.

## Технологический стек

- **Сборка:** Vite 8
- **Фреймворк:** React 19 + TypeScript 6
- **Маршрутизация:** React Router 7
- **Стили:** Tailwind CSS 4 + daisyui 5
- **Состояние и серверный кэш:** TanStack Query 5
- **Бэкенд (MVP):** Firebase Auth + Cloud Firestore
- **Валидация:** Zod 4
- **Тестирование:** Vitest + happy-dom + React Testing Library
- **Утилиты:** uuidv7

## Архитектурные заметки

Проект следует слоистой архитектуре для минимизации привязки к вендору:

- **`src/domain/`** — чистые TypeScript-модели и Zod-схемы.
- **`src/services/`** — Firebase-специфичные реализации, скрытые за интерфейсами (например, репозитории).
- **`src/context/`** и **`src/components/`** — представление и состояние приложения.

Такая изоляция позволяет заменить Firebase Auth/Firestore на собственный бэкенд (например, MongoDB или реляционную БД) без переписывания UI и доменной логики.

## Правила безопасности Firestore

Правила описаны в `firestore.rules`. Основные концепции:

- **Users** — чтение/создание/обновление собственного профиля; администраторы имеют полный доступ.
- **Associations** — публичное чтение; создание/изменение/удаление только для администраторов и менеджеров.
- **Players** — публичное чтение; создание/изменение/удаление администраторами или менеджерами основной ассоциации.
- **Tournaments** — публичное чтение, кроме черновиков; запись доступна владельцу, менеджерам host-ассоциации и администраторам.
- **Events** — публичное чтение; запись доступна владельцу, менеджерам host-ассоциации и администраторам.

Роль администратора проверяется через Firebase Custom Claims (`request.auth.token.admin == true`).

## Переменные окружения

Создайте файл `.env.local` в корне проекта с конфигурацией Firebase:

```env
VITE_FIREBASE_API_KEY=your_api_key
VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your_project_id
VITE_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
VITE_FIREBASE_APP_ID=your_app_id
```

## Быстрый старт

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Настройте Firebase в `.env.local`.
3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
4. Откройте URL из терминала (обычно `http://localhost:5173/`).

## Доменные сущности

Основные коллекции в Firestore:

- **tournaments** — метаданные турнира, игры, участники, статус и контроль времени.
- **players** — игроки в сёги с рейтингами и привязкой к ассоциациям.
- **associations** — группы, владеющие игроками, турнирами и мероприятиями.
- **events** — объединения турниров (этапы чемпионата, лиги и т.п.).
- **users** — профили пользователей приложения с локализованными именами.

Подробные определения полей см. в папке `schemas/`.
